# Agent Note: 原生跨会话记忆 — 确定性、可观测、人主导

Status: proposed

[English](2026-08-14-native-cross-session-memory.md) | 中文

## 问题

Harness 没有第一方跨会话记忆。一个想要"记住我在所有会话里都偏好 Vue 的 `<script setup>`"的用户，今天只有两条路，而两条都满足不了他：

- **通过 MCP 接入第三方记忆** — [第三方记忆示例](../../implemented/feature/2026-07-31-third-party-memory-mcp-examples.md)以默认关闭的 overlay 交付 Memorix、MCP Reference Memory 和 Engram。每个都需要固定的外部二进制、受监管的子进程或 HTTP 服务、厂商自有的存储与嵌入、厂商自有的工具 schema。对一条轻量偏好或项目约定而言，这是重炮打蚊子；而且记忆本身存在一个不透明的外部存储里，用户无法查看、模型无法审计——一个黑盒。
- **会话内回溯与日志引用** — [可回溯压缩](2026-07-06-recallable-compaction.md)与[跨会话引用](../../implemented/feature/2026-07-21-cross-session-references.md)处理的是情节历史：某个会话里发生了什么、从会话日志里搬出材料。两者都不是针对语义记忆（偏好、习惯、项目约定）的持久存储——那类应当比任何单个会话活得更久的东西。

结果是一个空白。持久的、第一方的、可检查的记忆并不存在。最接近的已交付路径把记忆变成了一个外部的、不可观测的黑盒——这既辜负了拥有它的用户，也辜负了本应能检查它的模型。

## 提案

在现有存储中枢之上，以三包能力缝的形式新增第一方跨会话记忆：

- `@deepseek-ai/dsh-memory` — 服务定义：`ctx.memory` 契约（remember / list / search / forget）、记忆词汇表、`memory/*` 事件。
- `@deepseek-ai/dsh-memory-basic` — 服务提供者：`ctx.storage.domain` 中的持久记录、BM25 关键词检索、状态生命周期（`suggested` → `auto` / `suggest`）。
- `@deepseek-ai/dsh-tool-memory` — 消费者：模型工具 `memory_save`、`memory_list`、`memory_search`、`memory_forget`，外加稳定记忆的 system-prompt section 与动态召回 context。

### 主导原则

这四条约束凌驾于一切实现细节之上。违反其中一条的设计，无论表现多好都是错的。

1. **人是所有者。** 模型只能以 `suggested` 状态写入记忆；任何记忆未经人工确认闸门都不得生效。模型绝不静默提升一条记忆。
2. **可观测先于精准。** 每条记忆都是明文、可列举、可删除。不存在隐藏记忆。过期或错误的记忆必须可发现、可修复，绝不能成为因为无人看得见而被反复召回的静默暗礁。
3. **明文是人机共享的审计窗口。** 因为记忆是可读文本，模型能自检其是否过期或出错——就像它维护文档和代码那样——这就是规划中的 v2。
4. **v1 确定性且缓存安全。** 稳定记忆以稳定 section 进入 system prompt（前缀稳定）；动态召回以运行时上下文快照进入（append-only 历史）。召回路径不做任何 LLM 调用，保持无密钥回放确定性。

### v1：确定性、可观测的记忆

v1 交付存储、四个工具与注入路径，热路径上无任何 LLM 调用。

| 工具 | 行为 |
|---|---|
| `memory_save` | 以 `suggested` 状态写入一条记忆；绝不自我提升 |
| `memory_list` | 列出全部记忆，可按命名空间（全局 / 项目）与状态过滤 |
| `memory_search` | BM25 关键词检索；每条命中携带命名其记忆键的来源标记 |
| `memory_forget` | 删除一条记忆，或降低其状态 |

存储是 `ctx.storage.domain`（[领域 KV 存储与工作区](../architecture/2026-07-24-domain-kv-storage-and-workspace.md)）之上的一个 `memory` 域，使用 json/sqlite 后端，因此记忆是用户可直接阅读、回放边界可重建的明文记录。检索采用 BM25——纯关键词函数，无嵌入依赖，召回可预测，未命中可解释。注入遵循缓存契约：稳定记忆进 system-prompt section，动态召回进运行时上下文快照，无命中时贡献零内容。

### v2：LLM 自检与学习

因为 v1 让记忆成为明文，v2 给模型一份针对它们的常驻工作：对照观测到的活动自检已存记忆是否过期或出错、提出更新、从 `session/event` 学习新的候选记忆——即 `suggested → confirmed` 的习惯流程。这是唯一调用模型的部分，且走请求路径之外的 `ctx.llm.stream()`。v2 是计划、不属于 v1，并依赖 v1 的明文：当记忆是不透明向量时，就无物可审。

### 与既有记忆面的关系

- 本 note 是[可回溯压缩](2026-07-06-recallable-compaction.md)的跨会话互补，后者的范围明确限定为会话内历史召回。
- 它不推翻[第三方记忆示例](../../implemented/feature/2026-07-31-third-party-memory-mcp-examples.md)：外部记忆服务器仍是重语义特性（向量检索、知识图谱）与厂商生态的路径。本 note 补上的是 MCP 路径过于沉重、过于不透明而覆盖不到的轻量、第一方、确定性路径。
- 它与[跨会话引用](../../implemented/feature/2026-07-21-cross-session-references.md)不同：后者把另一个会话日志里的材料搬进来；记忆是持久知识库，不是转录搬运。

## 备选方案

**直接用已交付的第三方 MCP 路径。** 拒绝：它要求外部二进制、受监管子进程、厂商自有的存储与嵌入，并把记忆变成用户无法查看、模型无法审计的不透明外部状态。对一条轻量偏好或项目约定，它是重炮打蚊子，也是一个黑盒——恰是本提案拒绝的"许愿机"。MCP 路径留给重语义特性；它不是轻量确定性记忆的归宿。

**让 v1 使用向量（语义）检索。** 拒绝：一条因向量始终语义相近而被静默召回的过期记忆，是一座不可观测的暗礁——没有明文可读，无从发现它已过期，也无从修复。语义检索可作为 v2 选项，但必须在可观测性与可修复性解决之后；它是凭可观测性条件准入，而非凭时间表准入。

**只做会话内召回路径，推迟跨会话。** 拒绝：召回回答"我们已经聊过什么"；记忆回答"我了解你如何工作"。两者都需要，且不共享底座——召回是会话日志的纯函数，记忆是 `ctx.storage.domain` 之上的持久存储。

**一个插件而非三包能力缝。** 拒绝：能力的存储与检索（Provider）和它的模型面（Consumer）各自独立演化——v2 替换或扩展 provider（BM25 → 语义），而一个 `/memory` 命令可以作为第二个 consumer 出现，无需改动定义。这一拆分与 compaction、bash 能力缝一致。

## 验收标准

- 能力缝以三个包交付，每文件 100% 覆盖率、HMR 释放测试，以及 memory 域的 `./invariant` 配套。
- 每次模型可见注入（稳定 section、召回 context、工具结果）都能从持久存储重建，并携带命名记忆键的来源标记。
- `memory_save` 只写入 `suggested` 状态；没有任何代码路径能在无确认闸门下提升记忆；`memory_list` 与 `memory_forget` 使任何已存记忆可发现、可移除。
- `memory_search` 是存储的纯函数——无 LLM 调用——因此召回确定且可无密钥回放；未命中可解释为"无关键词命中"。
- 过期或错误的记忆能通过 `memory_list` 找到，其来源可通过注入标记追踪，并能由人工或 v2 自检修复或移除。
- 存储域跨新会话持久（会话 A 写入、会话 B 读取），且 json 与 sqlite 后端均通过。

## 风险

- **可观测优先于精准是一笔有意的取舍。** BM25 的召回少于向量检索；能力在 v1 接受这一差距，因为可预测、可修复的召回胜过静默、不可修复的召回。
- **人工闸门增加摩擦。** 没有任何记忆自动生效，因此记忆的价值取决于用户的确认习惯；这是所有权代价，予以接受。
- **第一方存储是新的维护面。** 与 MCP 路径不同，DSH 现在拥有记忆存储与检索；范围被刻意收窄（BM25、明文、无嵌入）以保持该面足够小。
- **`storage.domain` 可见性是进程内的**（[领域 KV 存储与工作区](../architecture/2026-07-24-domain-kv-storage-and-workspace.md)）；第二个宿主进程或重连的 GUI 目前看不到实时的域变更。记忆存储继承这一限制，直到跨进程修订模式落地。
- **v2 是承诺，不是 v1。** 自检与学习以计划形式陈述；它们不在 v1 交付，其设计也未在此定稿。
